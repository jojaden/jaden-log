# MDX 뼈대

모든 컴포넌트를 쓰는 모습은 `src/content/posts/style-sample.mdx`(`/style-sample`)에 있다. 컴포넌트 목록과 속성의 원본은 `src/components/mdx/index.ts`와 각 `.astro` 파일의 `Props`다. 아래 표와 다르면 그쪽을 따른다.

## 글 안에 쓰지 않는 것

- `style=""`, `<style>`, 색 값, 여백 값, `<br>`, HTML 엔티티(`&mdash;`), h1, 배지, 손으로 쓴 목차, 글 끝 푸터, 시리즈 목록 상자를 쓰지 않는다.
- 글 머리(카테고리 경로, 제목, 부제, 날짜, 읽는 시간), 목차, 여백, 코드 하이라이팅, 이전·다음 글, 관련 글, 시리즈(`series.ts`), 댓글은 사이트가 만든다.
- 예외는 SVG 그림 안의 색과 크기, 그리고 그림 안 차례 효과의 `style="--d:…"`다([figures.md](figures.md)).

## frontmatter

```mdx
---
title: "Go sync.Pool — Put 이후엔 Bytes()도 남의 것이다"
description: "요청마다 버퍼를 새로 만들다가 sync.Pool로 바꿨는데, Put 뒤에 들고 있던 Bytes()가 다른 요청의 내용으로 바뀌어 있었다."
pubDate: 2026-10-22T10:00:00+09:00
category: "Go"
subcategory: "개념 정리"
tags: ["sync.Pool", "GC"]
---
```

| 필드 | 규칙 |
| --- | --- |
| `title` | `[식별자·개념] — [한국어 훅]`. ` — ` 앞은 큰 제목이 되고 뒤는 회색 부제가 된다([titles.md](titles.md)) |
| `description` | 도입 문단에서 문장 단위로 잘라 160자 이내로 쓴다. 문장 중간에서 자르지 않는다. 요약형 문장("이 글에서는 ~를 정리한다")으로 새로 쓰지 않는다 |
| `pubDate` | 한국 시간 `+09:00`까지 쓴다. 옮긴 글은 원문 날짜를 그대로 둔다. 가장 최근 글이 홈 대표 글이 된다 |
| `updatedDate` | 고친 날짜. 선택 |
| `category`, `subcategory` | `src/lib/site.ts`의 `CATEGORIES` 이름을 글자 그대로 쓴다(영어판도 한국어 값). "회고" 같은 성격은 카테고리가 아니라 태그로 표현한다 |
| `tags` | 식별자·개념 위주로 2~5개 쓴다. `/`를 넣지 않는다. 태그 주소가 깨져서 빌드가 실패한다(예: `net/http` 대신 `HTTP 클라이언트`) |
| `draft: true` | 쓰는 중인 글. 개발 서버에서만 보인다. 발행할 때 지운다 |
| `hidden: true` | 페이지는 만들되 목록, RSS, 사이트맵에서 뺀다 |
| `stub: true` | 본문을 아직 옮기지 않은 자리표시 글. 본문을 옮기면 지운다 |
| `tistoryId` | 옛 티스토리 글 번호. 옮긴 글에 남겨 둔다 |

파일 이름이 주소가 된다(`31.mdx` → `/31`). 옮긴 글은 티스토리 글 번호를, 새 글은 짧은 영문 소문자·하이픈 id(`k8s-image-pull`)를 쓴다.

## 본문 순서

```mdx
<Lead>
도입 문단 3~4문장. 무슨 일이 있었는지부터 쓴다.
</Lead>

<Summary>
1. 첫째 요약 문장.
2. 둘째 요약 문장.
3. 셋째 요약 문장.
</Summary>

## 첫 h2, 가능하면 질문형
```

h2에는 자동으로 번호가 붙어 목차가 된다. `<Lab title>`은 목차에 `└`로 들어가고 h3는 들어가지 않는다. 그래서 h2 제목이 곧 목차 문구다. 본문은 h2부터 쓰고 h3를 건너뛰지 않는다.

## 컴포넌트 (import 없이 쓴다)

| 컴포넌트 | 쓰임과 규칙 |
| --- | --- |
| `<Lead>` | 도입 문단. 글 맨 앞에 한 번 |
| `<Summary>` | 세 줄 요약(`1. 2. 3.` 목록). 15분 넘게 읽히는 개념 정리 글에만 쓰고, 도입 바로 뒤에 둔다 |
| `<Figure caption cover wide>` | 인라인 SVG 그림. 캡션은 그림에서 먼저 볼 곳을 짚는 사실 한 줄이다. `cover`는 표지로 쓴다는 뜻이고, `wide`는 본문보다 넓게 그린다. 그리는 법은 [figures.md](figures.md) |
| `<Lab title>` | 🧪 직접 해 보기(파란 상자). h2로 쓰지 않는다. 제목은 주장문 한 줄이고 "직접 해보기 —" 같은 접두사를 붙이지 않는다. 실제로 돌린 값만 싣는다 |
| `<Note title>` | 제목 달린 곁가지 상자: 대상 독자, 버전·환경 차이, 도구별 차이, 흔한 오해처럼 본문 흐름 밖의 내용을 담는다. 앞 내용을 요약하는 상자로 쓰지 않는다. 글당 2개까지. 이모지와 경구 마무리를 쓰지 않는다 |
| `<Compare>` + `<Side title tone>` | 좌우 비교 카드 2~3칸. `tone="good"`은 ✓, `"bad"`는 ✕, 없으면 중립이다. 좋은 예와 나쁜 예 코드는 주석 `// ✓` 대신 이것을 쓴다 |
| `<Stats items={[{label, value, from?, note?}]}>` | 전후 숫자 카드. 실측값만 쓰고 `note`에 측정 조건을 적는다 |
| `<Bars title note shrink items={[{label, value, display?, hi?}]}>` | 가로 막대 비교. 화면에 들어오면 막대가 자란다. `hi`(강조)는 한 항목만 준다. `shrink`는 단계마다 줄어드는 양(예: 남은 시간 예산)을 계단식으로 깎아 보여 준다. 같은 그림을 SVG 막대로 그리지 않는다 |
| `<Carousel label>` + `<Slide title>` | 같은 주제의 사례를 3~5장 넘겨 보기. 순서가 중요하거나 꼭 다 읽어야 하는 내용에는 쓰지 않는다 |
| `<mark>` | 형광펜. 글당 2~3개, 문단의 핵심 구절 하나에만 |
| `[^이름]` | 각주. 버전 이력, 출처, 곁가지 설명을 담는다. 본문 흐름을 끊는 괄호 설명을 여기로 옮긴다 |
| `> 인용` | 다른 사람의 말이나 문서 인용, 그때 내가 세운 가설, 흔한 오해, 에러 원문. 쓰는 법은 [voice.md](voice.md) "남의 말 인용" |
| `### h3` | 가설 #1·#2, 날짜, 단계처럼 h2 안의 작은 단계. 목차에는 들어가지 않는다 |

## 인라인 코드

| 종류 | 쓰는 법 | 보이는 모양 |
| --- | --- | --- |
| 식별자(함수, 타입, 필드, 설정 키) | `` `sync.Pool` `` | 파란 칩 |
| 경로, 명령 | `<C k="path">/etc/app/config.yaml</C>` | 회색 칩 |
| 에러, 상태 문자열 | `<C k="err">OOMKilled</C>` | 주황 칩 |
| 측정값 | `<C k="num">800MB</C>` | 칩 없이 굵은 숫자 |

한 문단에 칩이 다섯 개를 넘으면 문장을 나누거나 코드 펜스로 뺀다.

## 코드 카드

고정폭으로 보여 주는 것은 전부 코드 펜스에 넣는다. 실행 결과, 설정, 의사코드, 로그, 에러 문자열, 셸 명령이 모두 여기에 해당한다.

````mdx
```go title="pool.go"
func render(w io.Writer, v any) error { … }
```

```text frame="terminal" title="실행 결과"
$ go test -bench=Render -benchmem
BenchmarkRender/pool-10    2000000    611 ns/op
```
````

- 펜스마다 `title`을 붙인다. 소스 코드는 파일 경로를 쓰고, 스니펫이라도 파일명을 붙인다(`main_test.go · 전체 테스트`).
- 실행 결과는 `frame="terminal"`로 쓰고, 명령은 `$ `를 붙여 첫 줄에 합친다. 명령 한 줄짜리 창은 따로 두지 않는다. 홈 카드가 비어 보인다.
- 실측하지 못한 출력은 title에 `예상 출력`이라고 쓴다.
- 줄 강조는 `{3-5}`, 바꾼 줄은 `del={2} ins={3-6}`로 표시한다.
- 출력 카드 바로 뒤에는 봐야 할 줄과 그 뜻을 1~2문장으로 쓴다. 출력을 말로 다시 옮기지 않는다.
- 코드 바로 뒤에 출력 카드를 두면 둘이 붙어 보이고, 표지로는 두 창이 겹쳐 나온다. 표지 창에는 앞 14줄만 들어가니 첫 줄부터 핵심이 보이게 짠다.

## 표

- 마크다운 표는 가로 스크롤 상자에 자동으로 담긴다. 첫 행이 머리글이 된다.
- 표 칸 안의 인라인 코드는 줄바꿈되지 않는다. 식별자가 글자 중간에서 끊기는 것보다 스크롤이 낫기 때문이다.
- 폭 390에서 스크롤이 70px를 넘으면 칸 내용을 줄인다. 머리글을 짧게 하거나, 설명은 본문으로 빼거나, 열 하나를 문장으로 옮긴다.
- 측정을 다룬 글은 `알 수 있는 것 / 알 수 없는 것` 표로 한계를 보여 줄 수 있다. 매 글에 넣으면 그것도 틀이 되니, 짧은 문단이 더 맞으면 문단으로 쓴다.
- 재현 조건을 바꿔 가며 돌린 결과, 사건 시간표(시각, 상태, 한 일), 비용·기간 비교는 표가 잘 맞는다.

## 글 끝

- `## 참고 자료`: 공식 문서, 릴리스 노트, 이슈, 커밋, 원 발표 같은 1차 자료의 링크 목록. 있는 글만 둔다.
- `## 고친 내용`: 발행 뒤 결론이 바뀌는 수정을 날짜와 함께 한 줄씩 남긴다. frontmatter `updatedDate`도 바꾼다.

## 기호

- 대시는 `—`(U+2014) 문자를 그대로 쓰고, 하이픈 `-`으로 대신하지 않는다.
- 나열은 `·`, 생략은 `…`로 쓴다.
