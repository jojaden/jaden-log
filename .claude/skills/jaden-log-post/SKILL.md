# Jaden.log 글 쓰기

글 한 편은 한국어판 `src/content/posts/<id>.mdx`와 영어판 `src/content/posts/en/<id>.mdx`, 두 파일로 이뤄진다. 저장소 `CLAUDE.md`의 영어판·시리즈·표지 규칙은 이 스킬과 함께 지킨다. 둘이 다르면 `CLAUDE.md`를 따른다.

글은 사용자 이름으로 나간다. 문장은 사용자가 겪은 일을 사용자 목소리로 쓰고, 사용자가 하지 않은 경험은 지어내지 않는다. 지어 넣을 수밖에 없었던 문장은 9단계 보고에 따로 적는다.

## 절차

1. **재료 모으기.**
   - 티스토리 글을 옮길 때는 `python3 .claude/skills/jaden-log-post/scripts/dump.py <id> <스크래치패드>/p<id>.html`로 원문을 뽑는다. 이 스크립트는 속성을 지우고 SVG를 `[SVG: 설명 | 글자들]` 한 줄로 줄인다.
   - 저장소에 있는 stub 글의 frontmatter는 그대로 이어 쓴다: `pubDate`, `tistoryId`, `category`, `subcategory`.
   - 완료 기준: 원문의 주장, 코드, 수치, 그림을 목록으로 다 뽑았다.
2. **사실 확인.**
   - 원문의 주장을 하나씩 확인한다. 코드는 스크래치패드에 모듈을 만들어 실제로 돌린다.
   - 출력이 원문과 같으면 그대로 쓴다.
   - 환경 때문에 다르면 원문 수치를 두고 내 환경 결과를 한 단락 덧붙인다. 이때 OS/아키텍처와 버전을 적는다.
   - 틀린 주장은 고치고 보고 목록에 올린다. 확인하지 못한 주장도 보고 목록에 올린다.
   - 완료 기준: 실행 결과 카드마다 "실측" 아니면 "예상 출력"이 정해졌다.
3. **뼈대 짜기.**
   - 원자료의 순서와 제목을 옮기지 않는다. [structure.md](structure.md)의 유형별 흐름으로 다시 짠다.
   - 원문의 손으로 쓴 목차와 시리즈 상자는 버린다. 사이트가 만든다.
4. **한국어판 쓰기.**
   - 그림은 스크래치패드에 생성기(`scripts/svg.py`를 불러 쓰는 파이썬)를 만들어 한국어·영어 SVG를 함께 뽑는다.
   - 본문은 템플릿 자리(`{{키}}`)에 그림을 끼워 조립한다.
   - 옮기는 글은 원문을 그대로 옮기지 않는다. 바뀐 컴포넌트와 효과에 맞게 고치고, AI 말투와 되풀이되는 문장, 사용자가 쓰지 않을 머리말을 걷어낸다.
5. **영어판 쓰기.** [english.md](english.md)를 따른다.
6. **시리즈.** 이어지는 글이면 `src/lib/series.ts`에 편을 추가한다. 이름은 한국어·영어 둘 다 쓴다.
7. **검사.** 아래를 다 돌리고 ⚠를 없앤다. 못 없앤 것은 이유와 함께 보고에 올린다.
   - `npx astro build`가 통과한다. 태그에 `/`가 있으면 태그 페이지가 깨진다.
   - `npm run check:title -- <id> en/<id>`
   - `npm run check:voice -- <id> en/<id>`
     - ⚠가 뜬 문장을 [voice.md](voice.md)의 "고칠 때 순서"대로 고친다.
     - ⚠가 없어도 문단 끝 문장과 착각 문장은 직접 읽는다.
   - `npx astro preview --port 4329`를 띄우고 `npm run check:layout -- <id> en/<id>`를 돌린다. 기준은 셋이다.
     - 그림 여유가 음수가 아니다.
     - 페이지 폭이 화면 폭과 같다.
     - 폭 390에서 표 스크롤이 70px 안쪽이다.
   - `npm run check:layout -- --shots <스크래치패드>/shots <id> en/<id>`로 스크린샷을 남기고 직접 본다. 볼 것은 다음과 같다.
     - 작은 글자나 빽빽한 카드가 없다.
     - 바깥 카드 폭에 비해 안쪽 카드가 작지 않다.
     - 넓은 카드에서 글자가 왼쪽에만 몰려 있지 않다.
8. **표지.** `CLAUDE.md`의 "표지 고르기"를 따른다. 한국어판과 영어판을 각각 고른다.
9. **보고하고 기다리기.** 사용자에게 아래를 짧게 알리고, "푸시"라는 말을 기다린다.
   - 옮기며 바꾼 것
   - 고친 사실, 확인하지 못한 주장
   - 내 환경에서 다르게 나온 결과
   - 지어 넣은 1인칭 문장(원문 그대로 인용)
   - 남은 ⚠와 그 이유
   - 고른 표지
10. **푸시.** 사용자가 "푸시"라고 하면 한다.
    - 그 글의 파일만 커밋한다: 두 mdx 파일, 바꿨다면 `series.ts`.
    - 커밋 메시지 형식은 `글 이전: <제목> (/<id>, <시리즈 몇 편이면 적는다>, 한국어·영어)`이다. 새 글이면 `글 추가:`로 시작한다.
    - `main`에 push하면 Cloudflare Workers로 배포된다.
    - `gh api repos/jojaden/jaden-log/commits/<sha>/check-runs --jq '.check_runs[] | "\(.name) \(.status) \(.conclusion)"'`로 배포가 성공했는지 확인한다.

사용자가 그림이나 문장을 고쳐 달라고 하면 고친 뒤 7단계 검사를 다시 돌리고 9단계로 돌아간다.
