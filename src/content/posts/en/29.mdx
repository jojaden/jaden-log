<Lead>
While preparing to change jobs, I searched for postings, judged whether each one fit me, and reworked my resume every week. [jobhunt](https://github.com/jojaden/jobhunt) is the agent skill I built to hand that work to an AI agent. The LLM only labels each line of a posting; scripts compute the scores and numbers. Every screen below comes from jobhunt's demo mode, with made-up companies and a made-up person. The tool's own screens are in Korean.
</Lead>

## Install it, then just ask

```bash title="Install"
curl -fsSL https://raw.githubusercontent.com/jojaden/jobhunt/main/install.sh | bash

# to connect through the Claude Code or Codex plugin
claude plugin install jobhunt --marketplace jojaden/jobhunt
codex plugin marketplace add jojaden/jobhunt && codex plugin add jobhunt@jobhunt
```

| Say | What happens |
| --- | --- |
| "Find postings" | `jobhunt weekly` collects, new postings get a first pass against my criteria, then a tracker |
| (posting URL) "How's this one?" | Condition checks, a requirement-to-experience map, a score, and a strategy |
| "Prepare company A and company B" | Research on each posting's company, role, and hiring process saved as prep notes, then an offer to tailor the resume |
| "Make a resume for this posting" | A yaml from the evaluation's plan and the prep notes, a PDF build, checks, and fixes until it passes |
| "Run a mock interview" | One question at a time, follow-ups on my answers, short feedback on each |
| "I passed the resume screen" | The tracker updates; once results pile up, it suggests criteria changes |

## Scripts and the agent split five stages

Work that needs no judgment goes to scripts; reading a posting and judging it goes to the agent. The two never call each other. They read and write the same files in the <C k="path">data/</C> folder.

```yaml title="data/search/judgments/ganada_backend.yaml · fictional posting"
company: Ganada
title: Backend Engineer
gates: { location: pass, language: pass, stack: pass, years: pass, employment: pass, comp: pass }
```

Meeting every requirement still leaves the posting in band C when the key nice-to-have (`key`) is unmet, and band A still stops at 3.9 when the core domain is new to me.

## The same steps in any agent

The single source of guidance is `AGENTS.md`; `CLAUDE.md` only imports it. Records live outside the tool, so they survive updates even when it's installed as a plugin.

<Compare>
<Side title="Records inside the tool folder" tone="bad">
A marketplace or plugin lands in a cache folder the agent manages, and an update swaps the whole versioned folder. Records that build up over time have nowhere to stay.
</Side>
<Side title="Tool and records apart (jobhunt now)" tone="good">
The tool lives in a folder uv manages, and records live separately in <C k="path">~/jobhunt/data</C>. Both `jobhunt update` and a plugin update replace only the tool.
</Side>
</Compare>

| Safety net | What it catches |
| --- | --- |
| 150 unit tests (no network) | Collector response changes, regressions in filters, dedupe, and scoring, malformed resume yaml |
| mypy type checks | Postings or judgments passed with the wrong keys or types, modules that break the collector contract (`Protocol`) |
| CI (Ubuntu and macOS × Python 3.10 and 3.12) | Code that only works on my machine, installer errors, resume build failures |
| Pre-commit hook + main protection | Commits containing personal data or contact details, pushes that skip PRs and CI |
| Codex code review (review rules in `AGENTS.md`) | The places this repo has had bugs: data/ formats, telling provider errors apart, comparing postings, personal data, API keys |

## What it builds on, and what it won't do

It started from [career-ops](https://github.com/santifer/career-ops). I borrowed its ideas but built the parts that collect and read Korean postings from scratch.

| Borrowed | Built new |
| --- | --- |
| A skill split into modes (find, evaluate, resume, record) | 18 collectors for Korean job sites, plus career-site discovery |
| Tool in git, personal data local | Judgment files that label postings line by line, and a scoring script |
| Personal files that improve with use | A Korean resume PDF builder, a style checker, a cover-letter length checker |
| A person makes the final call | Guidance that runs the same way in any AI agent |

| Won't do | Instead |
| --- | --- |
| Work around bot blocking, or collect where robots.txt says no | Leave it for a person to read, or skip it |
| Read interview reviews behind a login | Mark them "couldn't verify" |
| Write experience or numbers without evidence | Tag the line [확인 필요] ("needs checking") |
| Submit applications | I press the button myself |

What changed most while building this was how I decide what to hand to an AI. Now the LLM reads and labels posting lines, scripts do the math, and I decide whether to apply.
