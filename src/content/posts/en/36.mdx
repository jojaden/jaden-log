<Lead>
The last post was about what a container sees, and this one is about how much it uses. Write `limits.cpu: 500m` in Kubernetes and the node's cgroup file `cpu.cfs_quota_us` gets 50000, so the kernel hands out that much CPU every 100 ms. I built cgroups by hand without containers, put limits on them, and then read on the node which files hold a Kubernetes pod's limits.
</Lead>

<Note title="Who this is for">
I wrote this for people who set requests and limits but have never seen how those values reach the kernel. Telling OOMKilled from Evicted is covered in the [requests and limits post](/en/30).
</Note>

## A cgroup is a directory under /sys/fs/cgroup

A cgroup is a kernel feature that groups processes to count and limit their CPU and memory use, and each group is a directory. I started three pods with different QoS classes and looked up where each nginx lives.

`free` reads `/proc/meminfo`, and that file is not hidden by any namespace. So a program that wants to know its own limits has to read the cgroup files itself. Since 1.25 the Go runtime reads the CPU quota to set `GOMAXPROCS`, but on a v1 node like this one, where containers share the node's cgroup namespace, it builds the wrong path and can't read the quota (fixed in 1.26, see the [GOMAXPROCS post](/en/21)). It doesn't read the memory limit, so we still need to set `GOMEMLIMIT` (see the [GOMEMLIMIT post](/en/22)).

## Wrap-up

- A cgroup is a directory under `/sys/fs/cgroup`. Make the directory, write a limit as a number, and add a PID, and the kernel counts that process from then on.
- Memory that hits its limit ends with an OOM kill inside that cgroup (even with 7 GB free on the node), and CPU that uses up its quota stops for the rest of the period.
- The quota applies to the whole cgroup, so two threads with a one-CPU quota topped out at 99% combined.
- Kubernetes writes `limits.cpu` to `cpu.cfs_quota_us`, `limits.memory` to `memory.limit_in_bytes`, and `requests.cpu` to `cpu.shares`. `requests.memory` goes into `oom_score_adj`, not a cgroup file.
- `free` and `nproc` inside a container show node values. In v2 the trees merge into one and the files become `cpu.max` and `memory.max`.
