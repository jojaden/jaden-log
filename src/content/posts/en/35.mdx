<Lead>
In the last post the slowest step in starting a pod was the sandbox, and I waved off what happens inside it as an isolated space. So this time I left Kubernetes out and built that isolation piece by piece with plain Linux commands. Run `ps` inside the pod and nginx is PID 1, but find the same process on the node and it's PID 3756479. A container is an ordinary process running on the node's kernel, and the kernel uses namespaces to change only what that process can see.
</Lead>

<Note title="Who this is for">
This is for people who use containers but have never looked at their processes from the node. CPU and memory limits (cgroups) get their own [cgroups post](/en/36).
</Note>

## Each kernel resource gets its own namespace

Some kernel resources exist once per system: the process ID table, network devices and routes, the mount list, the hostname. A Linux namespace wraps one kind so that the processes inside see their own copy, and each process's namespaces are links under `/proc/<pid>/ns/`.

There are eight kinds.[^time] A shared user namespace means root inside the container is the same user as root on the node, a topic for part 4, on privileges.

The Namespace you create with `kubectl create ns` is an API object that only shares its name with Linux namespaces. Whatever Namespace a pod is in, it gets its own Linux namespaces. The cgroup namespace in the list of eight has nothing to do with limits either; it only hides how a process's own cgroup path looks.

### Without a handler, even SIGTERM is dropped

An ordinary process exits on SIGTERM even without a handler. PID 1 gets only the signals it handles, except SIGKILL and SIGSTOP sent from an ancestor namespace.

<Lab title="sleep as PID 1 kept running after SIGTERM">
<Shot src="/img/35/signal.webp" w={1720} h={942} phone={{ src: '/img/35/signal-phone.webp', w: 1170, h: 1752 }} name="lab-node:/tmp/jd-l1" alt="sleep 1000 in a new PID namespace is node PID 3760660 with NSpid 3760660 1 and SigCgt 0000000000000000. `SigCgt` is the bitmap of signals the process has handlers for, and for sleep it is all zeros. A second after SIGTERM, sleep was still running, and it disappeared after SIGKILL. For comparison, an ordinary sleep ended at once on the same SIGTERM with exit code 143 (128 + 15).

When you delete a pod, the kubelet goes through the runtime to send SIGTERM (or the image's `STOPSIGNAL`, if set) to the container's PID 1, and sends SIGKILL if it is still there after the grace period. If a startup script is PID 1, the pod waits the full 30 seconds and then ends with exit code 137 (128 + 9).

### It adopts orphans, and when it exits everything goes

An orphan, whose parent exits first, is adopted by systemd on the node and by PID 1 inside a PID namespace.

<Lab title="sleep 700 lost its parent and became a child of PID 1">
<Shot src="/img/35/orphan.webp" w={1720} h={796} phone={{ src: '/img/35/orphan-phone.webp', w: 1170, h: 1542 }} name="lab-node:/tmp/jd-l1" alt="ps inside the new PID namespace: PID 1 is bash -c (sleep 700 &); sleep 800, PID 3 sleep 700 has PPID 1, PID 4 is sleep 800. When PID 1 exits, the kernel sends SIGKILL to every other process in the namespace, which is why everything in a container ends at once, without cleanup, when its main process exits.

## Commands used in the lab

Here are the commands from the lab, with what each one shows. `<…>` marks a value you fill in.

```bash title="Commands for looking at namespaces"
# Which namespace a process is in for each kind; the number in brackets is the namespace ID
ls -l /proc/<pid>/ns

# The node PID and inner PID on one line, and the bitmap of handled signals
grep -E 'NSpid|SigCgt' /proc/<pid>/status

# How many processes a namespace has, and where it is bind-mounted
lsns -t net -p <pid>
findmnt -t nsfs
```

```bash title="Commands for creating and entering namespaces"
# Run one command in a new uts or net namespace
unshare --uts sh -c 'hostname jd-box; hostname'
unshare --net ip -br link

# A new PID namespace. --fork makes the child PID 1, --mount-proc mounts a fresh /proc
unshare --pid --fork --mount-proc bash

# Enter only the namespaces you pick: -n for net, -p for pid, -m for mnt
nsenter -t <pid> -n ss -ltn
nsenter -t <pid> -p -m ps -o pid,ppid,stat,cmd -e
```

```bash title="Commands for finding and handling processes"
# Match the full command line. -a prints it, -x requires an exact match
pgrep -fa '[s]leep 1000'             # [s] keeps pgrep from matching its own shell
pgrep -fx 'sleep 1000'

# Walk up the parents. -s shows ancestors, -p shows PIDs
pstree -sp <pid>

# Ask the runtime (CRI) for a container's PID
crictl inspect -o go-template --template '{{.info.pid}}' <container id>

# Send signals. TERM gives a chance to clean up, KILL ends it at once
kill -TERM <pid>; kill -KILL <pid>
```

## Wrap-up

- A container is a process the node's kernel runs directly. The nginx that was PID 1 inside the pod was PID 3756479 on the node, and the `NSpid` line held both numbers.
- There are eight Linux namespace kinds (pid, net, mnt, uts, ipc, user, cgroup, time), and processes with the same number under `/proc/<pid>/ns` are in the same namespace. A Kubernetes Namespace is an API object that only shares the name.
- `unshare` moves the caller, but the PID namespace starts with the children. Without `--fork`, the first child became PID 1, exited, and the next fork failed with `fork: Cannot allocate memory`.
- PID 1 only receives signals it handles (SIGTERM was dropped), adopts orphans, and when it exits everything inside is killed with SIGKILL. A startup script should either `exec` the server into PID 1 or put an init such as tini in front.
- Containers in a pod share net, ipc, and uts and keep their own pid and mnt. The net namespace was bind-mounted at `/run/netns/cni-…`.

[^dev]: namespaces(7) says two processes are in the same namespace when their `/proc/<pid>/ns/xxx` links have both the same device number and the same inode number. Within one node, comparing this number is enough. Lines ending in `_for_children`, such as `pid_for_children`, are where the process's future children will go.

[^time]: The lab node runs kernel 4.18, yet `time` was there. Upstream added that kind in 5.6, so it looks like the distribution kernel (Rocky 8) backported it.

[^enomem]: According to pid_namespaces(7), once the init of a PID namespace exits, `fork` in that namespace fails with ENOMEM.
