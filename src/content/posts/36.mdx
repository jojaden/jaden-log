<Lead>
지난 글은 컨테이너가 무엇을 보는지였고, 이번에는 얼마나 쓰는지다. 쿠버네티스에 `limits.cpu: 500m`을 적으면 노드의 cgroup 파일 `cpu.cfs_quota_us`에 50000이 적히고, 커널은 100ms마다 그만큼만 CPU를 준다. 컨테이너 없이 cgroup을 손으로 만들어 한도를 걸어 보고, 쿠버네티스 파드의 한도가 어느 파일에 적히는지 노드에서 읽어 봤다.
</Lead>

<Note title="누구를 위한 글인가">
requests와 limits를 쓰고 있지만 그 값이 커널에 어떻게 전해지는지는 본 적 없는 사람을 기준으로 썼다. OOMKilled와 Evicted를 가르는 법은 [requests·limits 편](/30)에 있다.
</Note>

## cgroup은 /sys/fs/cgroup 아래 디렉터리다

cgroup은 프로세스를 묶어 CPU와 메모리 사용량을 세고 제한하는 커널 기능이고, 묶음 하나가 디렉터리 하나다. QoS가 다른 파드 셋을 띄우고 각 nginx가 든 자리를 찾았다.

## 실습에서 쓴 명령

```bash title="cgroup을 읽는 명령"
# 프로세스가 컨트롤러마다 어느 cgroup에 있는지 (v1은 컨트롤러별 줄, v2는 0::/경로 한 줄)
cat /proc/<pid>/cgroup

# 한도와 통계. -1과 아주 큰 수는 제한 없음
cat /sys/fs/cgroup/memory/<경로>/memory.limit_in_bytes
cat /sys/fs/cgroup/cpu,cpuacct/<경로>/cpu.cfs_quota_us
cat /sys/fs/cgroup/cpu,cpuacct/<경로>/cpu.stat        # nr_periods · nr_throttled · throttled_time

# 이 노드가 v1인지 v2인지. cgroup2fs면 v2, tmpfs면 v1
stat -fc %T /sys/fs/cgroup
```

```bash title="cgroup을 만드는 명령"
mkdir /sys/fs/cgroup/memory/jd-l2                    # 만들기
echo 100M > /sys/fs/cgroup/memory/jd-l2/memory.limit_in_bytes
echo $$ > /sys/fs/cgroup/memory/jd-l2/cgroup.procs   # 지금 셸을 넣는다. 자식도 따라 들어간다
rmdir /sys/fs/cgroup/memory/jd-l2                    # 안에 프로세스가 없어야 지워진다
```

## 실습 환경과 한계

실습은 실습 서버(Rocky Linux 8.10, 커널 4.18, x86_64, 4 vCPU, 메모리 15.4GiB, swap 없음)에서 했다. cgroup은 v1이고, RKE2 v1.28.2 단일 노드가 systemd cgroup 드라이버를 쓴다. 실측 화면은 명령과 출력을 그대로 기록해 터미널 모양으로 그려 찍었고, 출력은 고치지 않았다.

#!/bin/bash
# cpu-run.sh <쿼터 µs, -1은 제한 없음> [돌릴 개수]
# jd-l2 cgroup에 쿼터를 걸고 spin.sh 를 넣은 뒤, 5초 동안 쓴 CPU와 throttling 걸린 주기 수를 찍는다

for i in $(seq ${2:-1}); do ./spin.sh & echo $! > $C/cgroup.procs; disown; done
sleep 1; read u0 < $C/cpuacct.usage; s0=($(awk '{print $2}' $C/cpu.stat))
sleep 5; read u1 < $C/cpuacct.usage; s1=($(awk '{print $2}' $C/cpu.stat))
kill $(cat $C/cgroup.procs); sleep 0.3
echo "quota=$1 spin=${2:-1}  cpu=$(( (u1-u0)/50000000 ))%  throttled=$((s1[1]-s0[1]))/$((s1[0]-s0[0])) periods"

## 정리

- cgroup은 `/sys/fs/cgroup` 아래 디렉터리다. 디렉터리를 만들고, 한도를 숫자로 쓰고, PID를 넣으면 그 프로세스부터 커널이 센다.
- 메모리는 한도에 닿으면 그 cgroup 안에서 OOM kill로 끝나고(노드에 7GB가 남아 있어도), CPU는 주기마다 쿼터를 다 쓰면 남은 시간만큼 멈춘다.
- 쿼터는 cgroup 전체에 걸려서 실행 흐름 둘에 CPU 1개 쿼터를 주면 합쳐서 99%에서 막혔다.
- 쿠버네티스는 `limits.cpu`를 `cpu.cfs_quota_us`로, `limits.memory`를 `memory.limit_in_bytes`로, `requests.cpu`를 `cpu.shares`로 쓴다. `requests.memory`는 cgroup 파일이 아니라 `oom_score_adj`에 반영된다.
- 컨테이너 안의 `free`와 `nproc`는 노드 값을 보여 준다. v2에서는 나무가 하나로 합쳐지고 파일 이름이 `cpu.max`, `memory.max`로 바뀐다.

다음 편에서는 컨테이너의 `/`가 어디서 오는지, 이미지 레이어가 overlayfs로 겹쳐지는 자리를 노드에서 열어 볼 생각이다.
