## 설치하고 말로 시킨다

```bash title="설치"
curl -fsSL https://raw.githubusercontent.com/jojaden/jobhunt/main/install.sh | bash

# Claude Code·Codex 플러그인으로 연결할 때
claude plugin install jobhunt --marketplace jojaden/jobhunt
codex plugin marketplace add jojaden/jobhunt && codex plugin add jobhunt@jobhunt
```

| 이렇게 말하면 | 일어나는 일 |
| --- | --- |
| "공고 찾아줘" | `jobhunt weekly`로 수집하고, 새 공고를 내 기준으로 1차 선별해 현황표로 |
| (공고 URL) "이 공고 어때?" | 조건 판정, 요건과 내 경험 대응표, 점수와 지원 전략 |
| "A사, B사 준비해줘" | 공고마다 회사·직무·전형을 조사해 준비 자료로, 끝나면 이력서를 맞출지 묻는다 |
| "이 공고용 이력서 만들어줘" | 평가 계획과 준비 자료로 yaml 작성, PDF 빌드, 검사, 수정 반복 |
| "모의 면접 해줘" | 한 문항씩 묻고 내 답에 꼬리질문, 답마다 짧은 피드백 |
| "서류 붙었어" | 현황표 갱신, 결과가 쌓이면 기준 조정 제안 |

## 어느 에이전트에서나 같은 절차로

지침 원본은 `AGENTS.md` 하나이고, `CLAUDE.md`는 그걸 불러오기만 한다. 기록은 도구 밖에 둬서 플러그인으로 깔아도 업데이트 때 사라지지 않는다.

<Compare>
<Side title="도구 폴더 안에 기록을 둘 때" tone="bad">
마켓플레이스·플러그인은 에이전트가 관리하는 캐시 폴더에 들어가고, 업데이트 때 버전 폴더째 바뀐다. 쌓아 둔 기록이 머물 자리가 없다.
</Side>
<Side title="도구와 기록을 나눌 때 (지금 jobhunt)" tone="good">
도구는 uv가 관리하는 폴더에, 기록은 <C k="path">~/jobhunt/data</C>에 따로 둔다. `jobhunt update`도 플러그인 갱신도 도구만 바꾼다.
</Side>
</Compare>

| 커밋 전 훅 + main 보호 | 개인 자료나 연락처가 섞인 커밋, PR과 CI를 거치지 않은 push |

## 참고한 도구와 하지 않는 일

출발점은 [career-ops](https://github.com/santifer/career-ops)였다. 아이디어는 가져왔지만, 한국 공고를 모으고 읽는 부분은 새로 만들었다.

| 가져온 것 | 새로 만든 것 |
| --- | --- |
| 모드로 나눈 스킬(찾기·평가·이력서·기록) | 한국 채용 사이트 수집기 18개, 회사 채용 사이트 찾기 |
| 도구는 git, 개인 자료는 로컬 | 공고를 줄 단위로 분류하는 판정 파일, 점수 계산 스크립트 |
| 쓸수록 기준이 쌓이는 개인화 파일 | 한국어 이력서 PDF 빌더, 문체 검사, 자기소개서 글자 수 검사 |
| 사람이 최종 결정한다는 원칙 | 어느 AI 에이전트에서나 같은 절차로 도는 지침 구조 |

| 하지 않는 일 | 대신 |
| --- | --- |
| 봇을 막는 사이트 우회, robots.txt로 막힌 곳 수집 | 사람이 읽는 방식으로 남기거나 쓰지 않는다 |
| 로그인 뒤에 있는 면접 후기 읽기 | "확인 못 함"으로 적는다 |
| 근거 없는 경험·수치 쓰기 | 문장에 [확인 필요]를 붙인다 |
| 지원서 제출 | 내가 직접 누른다 |

만들면서 가장 크게 바뀐 건 AI에게 일을 나눠 주는 기준이었다. 지금은 공고 문장을 읽고 분류하는 일은 LLM이, 숫자 계산은 스크립트가 하고, 지원할지 말지는 내가 정한다.
